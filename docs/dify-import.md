# Dify 工作流导入

1.1.0 支持从工作台顶部「导入」按钮选择 Dify 导出的 `.yml` / `.yaml` 文件。导入先创建全局工作流模板；用户从模板创建实例、核对模型并填写运行输入后，可以直接运行兼容子集。

## 使用步骤

1. 导入 Dify YAML，打开新生成的工作流模板并查看兼容状态。
2. 对 `review-required` 模板核对或重新选择每个 LLM/Agent 的 provider 与 model。
3. 从模板创建工作流实例；导入来源和兼容报告会随实例保留。
4. 点击“配置并运行”，填写由 Dify Start 变量转换出的工作流输入；同一个变量只需填写一次，会自动分发给所有引用节点。
5. Runtime 以确定性 DAG 顺序执行节点；运行完成后，历史摘要显示进入 Answer/End 的最终 Agent 输出。

`blocked` 模板可以查看和编辑，但运行前会由 Host 护栏拒绝，不会把占位 Agent 当作已适配能力执行。

## 转换边界

- `start`、`answer/end` 转换为原生启动和结束节点。
- `llm`、`agent` 转换为 Harness Agent 节点，保留模型身份、Prompt 和职责信息；Start 引用转换为运行输入，上游 Agent 引用转换为显式上下文依赖。
- 仅含单一上游变量的 `answer` 以及无结构化输出的 `end` 按直通结束节点处理。
- `tool`、知识检索、HTTP、代码、模板转换、条件、循环、迭代和未知节点会保留为可见占位，但兼容状态为 `blocked`，不能直接运行。
- Dify Flow 连线转换为原生 Flow 连线；固定图使用 `executionMode: dag`，不再由父模型临场猜测执行顺序。

转换器不会声称两种平台的节点具有天然等价语义。v1.1 的可运行范围有意收窄为 Start、LLM/Agent 和直通 Answer/End；其余能力等待后续适配器实现。

## 安全规则

- API Key、Authorization、Cookie、密码、Token 和 Dify credential 引用在解析阶段移除。
- 兼容报告只保存依赖身份，不保存密钥。
- 外部模型、工具、知识库和 HTTP 目标不会自动启用，必须在目标 Harness 环境重新绑定。

## 兼容状态

| 状态 | 含义 | 后续动作 |
|---|---|---|
| `ready` | 未发现结构或适配问题 | 打开模板复核后创建实例 |
| `review-required` | 存在非阻断兼容问题 | 核对/重绑模型并核对节点 Prompt、输入 |
| `blocked` | 存在不支持节点或图错误 | 完成适配或修改拓扑后再运行 |

模板的 `sourceImport` 字段保存来源版本、问题清单和依赖清单，后续可用于旧工作流优化与差异评估。
