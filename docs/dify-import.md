# Dify 工作流导入

1.1.0 支持从工作台顶部「导入」按钮选择 Dify 导出的 `.yml` / `.yaml` 文件。导入只创建全局工作流模板，不直接创建实例或启动运行。

## 转换边界

- `start`、`answer/end` 转换为原生启动和结束节点。
- `llm`、`agent` 转换为 Harness Agent 节点，保留模型身份、Prompt、输入引用和职责信息。
- `tool`、知识检索、HTTP、代码和模板转换节点会保留为待适配 Agent 占位，并要求重新绑定能力。
- `loop`、`iteration` 和未知节点会保留为占位，但兼容状态为 `blocked`。
- Dify 连线转换为原生 Flow 连线；可识别的 true/false 分支转换为通过/不通过条件。

转换器不会声称两种平台的节点具有天然等价语义。导入模板必须根据兼容报告复核后再创建实例。

## 安全规则

- API Key、Authorization、Cookie、密码、Token 和 Dify credential 引用在解析阶段移除。
- 兼容报告只保存依赖身份，不保存密钥。
- 外部模型、工具、知识库和 HTTP 目标不会自动启用，必须在目标 Harness 环境重新绑定。

## 兼容状态

| 状态 | 含义 | 后续动作 |
|---|---|---|
| `ready` | 未发现结构或适配问题 | 打开模板复核后创建实例 |
| `review-required` | 存在非阻断兼容问题 | 重绑定依赖并核对节点 Prompt、输入和分支 |
| `blocked` | 存在不支持节点或图错误 | 完成适配或修改拓扑后再运行 |

模板的 `sourceImport` 字段保存来源版本、问题清单和依赖清单，后续可用于旧工作流优化与差异评估。
